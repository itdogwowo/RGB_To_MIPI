# .esch2 格式與連線陷阱（實戰筆記）

這份是 `SKILL.md` 的補充，只放「會靜默壞掉」的細節。全部是實際踩過並用量測確認的。

---

## 1. 為什麼「全部沒有連接」

### 症狀
Agent 產生檔案 → 使用者用 EasyEDA Pro 打開 → 每隻腳都浮著，即使畫面上有線。

### 量測方法（用客戶端自己畫的板子當基準）

對每個腳位算兩種「接點」，數「有線端點落在上面」的數量：

| 接點定義 | 命中率（客戶端檔案） |
|---|---|
| 腳位錨點 (px, py) | 235 / 301 |
| 腳位外端點 | 23 / 301 |

→ 客戶端主要認錨點，但**不是全部**（有些腳位的線是 T 接、有些端點落在線中段）。
結論：**不要賭是哪一點，讓線跨過整隻腳。**

### 可靠畫法
```
起點 = 錨點 − 方向 × 6
終點 = 錨點 + 方向 × (腳長 + 28)
```
其中「方向」＝腳位朝外的單位向量，且要再依元件 rotation 旋轉。

### 垂直腳位（rot 90 / 270）特別容易錯
腳位旋轉代表「朝外」的方向：

| pin rot | 朝外方向（y 向上） |
|---|---|
| 0 | (−1, 0) |
| 90 | (0, −1) |
| 180 | (1, 0) |
| 270 | (0, 1) |

寫反的後果：線跑到元件體內側，41 隻腳全部沒接（真實案例：四邊出腳的 QFN 符號）。

## 2. `validate.js` 崩潰不是檔案壞

官方驗證器的 `docsOf()` 只認**完全等於** `{"type":"DOCHEAD"}` 的行；
客戶端存檔寫的是 `{"type":"DOCHEAD","ticket":192}`。

- 檔案本身合法、客戶端打得開
- `validate.js` 會解析出 0 個文件 → `Cannot read properties of undefined`

**不要為了迎合驗證器去改使用者檔案。** 改用幾何檢查（`scripts/verify_sch.py`）。
若是自己從零產生的檔案（DOCHEAD 是正規形式），`validate.js` 仍然好用。

## 3. `yAxisDirection`

- 只有原理圖家族有這個鍵；PCB 沒有。
- 缺省 ≡ `"down"`。
- 同一份檔案混用 → 電路與圖框上下鏡像，**看起來連著、其實沒連**。
- 客戶端存檔時會自動正規化（把 y 取負並補標記），所以「請使用者開檔後存一次」也能修。
- 自己產生記錄時，**要跟檔案裡既有記錄用同一個值**。

## 4. 記錄範圍與文件切割

檔案是一串文件，每份以 `DOCHEAD` 開頭：

```
DOCHEAD(SYMBOL) → META → CANVAS → PIN… → ATTR…
DOCHEAD(SYMBOL) → …
DOCHEAD(SCH_PAGE) → COMPONENT / WIRE / LINE / ATTR / TEXT …
```

- **新記錄要插進目標文件的區段**（下一個 DOCHEAD 之前）。
- 頁面文件不一定是最後一份；append 到檔尾很容易歸錯文件。
- 腳位 id（`e1`、`e3`…）**只在同一份文件內唯一**，跨文件會撞號。
  解析時務必「以文件為界」建表，否則會拿到別顆元件的腳名（真實踩過：
  顯示接頭的 30 隻腳被解析成觸控接頭的腳名）。

## 5. 匯入客戶端符號當 library entry

客戶端匯出的 SYMBOL 文件不能直接丟給 `add-symbol`：

1. `DOCHEAD` 正規化成 `{"type":"DOCHEAD"}`（否則 embedder 找不到切點，
   整份文件會被塞進 DEVICE，造成 `duplicate ticket` 與「Symbol attr references missing SYMBOL doc」）
2. `ticket` 從 1 重新編號，避免與其他文件撞號
3. 同名符號只留一份（例如泛用 SSD2828 與真實 69-pin 版本同名，要用腳位分佈區分：
   真實 IC 符號的腳位會分佈到 ±150，泛用版只有 ±20）

`scripts/mk_lib_entries.py` 已實作以上三步。

## 6. 常見的意外短路

| 類型 | 例子 | 檢查方式 |
|---|---|---|
| T 接 | 電容 stub 端點落在訊號線中段 | 端點到他人線段距離 < 0.3 |
| 端點重合 | 兩顆 LDO 的 stub 在 (400,785) 相遇（1V8 撞 3V3） | 同一座標出現兩個網路名 |
| 跨越 | 長 stub 跨過隔壁元件的腳 | 線段相交且無共同端點 |

修法一律是**移動元件或縮短 stub**，不要靠調順序。

## 7.5 NET 標籤錨點不可離開導線

「美化」NET 標籤時只准動 `fontSize` / `align` / 顏色，**不准動 `x/y`**。
把錨點從 stub 中點外移到線端之外，客戶端裡標籤就懸空在導線旁，
使用者看到的就是「連接位沒有連接好、文字沒有標記好」——即使電氣完全正常。
（真實案例：2026-10-27 U1 標籤美化把上下行錨點外移 19 單位，被回報斷線；全部還原後消失。）

另外：間距 10 的縱列標籤重疊，解法是 `fontSize: 7`，不是移錨點。
90° 縱排標籤在離線渲染器裡要先讀 ATTR 的 `rotation` 再畫，否則會誤判成重疊。
